# elt-bench-rl

An end-to-end RLVR environment that turns [ELT-Bench](https://github.com/uiuc-kang-lab/ELT-Bench)
into a trainable task for [tinker-cookbook](https://github.com/thinking-machines-lab/tinker-cookbook).

In one rollout the policy reads a task specification, configures extraction and loading
(Airbyte resources declared in Terraform), writes the transformation models (dbt), uses
execution feedback from a sandboxed shell and from SQL against the warehouse, and submits.
The reward is computed from the warehouse state after the episode ends: raw tables first,
then each data model compared against ground truth with ELT-Bench's own comparator.

The environment is warehouse-agnostic. Everything warehouse-specific sits behind the
`Destination` interface, so the same tasks, rewards and training loop run against DuckDB
(local, credential-free) or Snowflake (the official benchmark setup). Adding a warehouse is
one subclass; nothing else changes.

See [docs/DESIGN.md](docs/DESIGN.md) for the design: reward shaping, reward hacking, and
training efficiency.

## Install

```bash
uv sync                      # Python 3.12
uv sync --extra snowflake    # adds snowflake-connector-python
```

## 1. Credential-free local integration test

No API key, no warehouse account, no Docker.

```bash
uv run pytest -q
# 10 passed, 4 skipped
```

The suite runs full episodes on `tiny_shop`, a self-contained task generated by
`scripts/make_tiny_shop.py`: three source kinds (CSV, JSONL, SQLite), two data models, and
edge cases the grader has to handle (a customer with no orders, NULL prices, ties broken by
a stated rule). A scripted oracle policy scores 1.0; scripted failure and reward-hacking
policies score what they should. Unit tests cover the comparator, the reward modes, and
eval-SQL rewriting.

The four skipped tests need an ELT-Bench checkout. They load the official tasks and check
that the comparator agrees with `evaluation/eva_stage2.py` table by table:

```bash
git clone --depth 1 https://github.com/uiuc-kang-lab/ELT-Bench.git ../ELT-Bench
ELT_BENCH_REPO=../ELT-Bench uv run pytest -q
# 14 passed
```

## 2. Credentialed rollout on an official ELT-Bench task

Prerequisites, all from the benchmark's own setup:

* the ELT-Bench repository, and its ground-truth CSVs
  (`hf download tttjjj/elt_bench --repo-type dataset --local-dir ../ELT-Bench/ground_truth`),
* the source stack, `cd ../ELT-Bench/elt-docker && docker compose up -d`, which also provides
  the `elt-swe` image used as the per-rollout sandbox,
* Airbyte OSS deployed with `abctl` on the same Docker network,
* a Snowflake account prepared with the benchmark's `setup/destination/setup.sql`.

```bash
export TINKER_API_KEY=...
export SNOWFLAKE_ACCOUNT=... SNOWFLAKE_ADMIN_USER=... SNOWFLAKE_ADMIN_PASSWORD=...
export AIRBYTE_USERNAME=... AIRBYTE_PASSWORD=... AIRBYTE_WORKSPACE_ID=...

uv run python -m elt_rl.rollout tasks=eltbench task_names=amplitude \
    destination=snowflake eltbench_repo=../ELT-Bench \
    gt_dir=../ELT-Bench/ground_truth/gt_snowflake
```

This samples one rollout from the base model, grades the warehouse it leaves behind, and
prints the reward and the full grade report (per raw table, per data model, per column). The
transcript is written to `out_dir` (default `/tmp/elt_rl/rollouts`). The rollout's Airbyte
resources and its database are torn down afterwards.

Defaults that can be overridden: `SNOWFLAKE_ADMIN_ROLE` (`SYSADMIN`), `SNOWFLAKE_WAREHOUSE`
(`AIRBYTE_WAREHOUSE`), `SNOWFLAKE_AGENT_USER` (`AIRBYTE_USER`), `SNOWFLAKE_AGENT_PASSWORD`,
`SNOWFLAKE_AGENT_ROLE` (`AIRBYTE_ROLE`), `AIRBYTE_HOST_API_URL`
(`http://localhost:8000/api/public/v1/`), `AIRBYTE_API_DEFINITION_ID`.

## 3. Tinker RL optimization step

Against the local task, which needs only `TINKER_API_KEY`:

```bash
uv run python -m elt_rl.train tasks=local max_steps=1
```

Against an official task, with the setup from section 2:

```bash
uv run python -m elt_rl.train tasks=eltbench task_names=amplitude \
    destination=snowflake eltbench_repo=../ELT-Bench \
    gt_dir=../ELT-Bench/ground_truth/gt_snowflake \
    group_size=4 groups_per_batch=1 max_steps=1
```

Training is tinker-cookbook's RL loop over this environment: a group is `group_size` rollouts
of the same task, run concurrently in separate namespaces and sandboxes, and the advantage is
computed within the group from execution-derived rewards. Rewards, grade reports and
per-rollout metrics (`stage1_fraction`, `srdt_fraction`, `task_success`, tool-call counts) are
logged each step, and the grade report of every rollout is written under
`<log_path>/grades/<run>/`.

## Configuration

| Flag | Default | Meaning |
| --- | --- | --- |
| `model_name` | `Qwen/Qwen3.6-35B-A3B` | Any model Tinker serves ([models.json](https://tinker-docs.thinkingmachines.ai/tinker/models.json)). `Qwen/Qwen3-8B` and `openai/gpt-oss-20b` are cheaper, with a 32K context |
| `reward_mode` | `staged` | `staged`, `model_fraction`, or `binary` |
| `el_weight` | `0.2` | Share of the reward carried by extraction and loading |
| `column_credit` | `0.5` | Partial credit inside a data model, by matching columns |
| `transform_only` | `false` | Start from a post-EL snapshot and train only the transformation stage |
| `require_airbyte_provenance` | `true` for official tasks | Raw tables must carry Airbyte metadata and a succeeded sync job |
| `group_size` / `groups_per_batch` | `4` / `2` | Rollouts per group, groups per batch |
| `max_turns` | `60` | Tool calls per episode |
| `max_trajectory_tokens` | `32768` | Episode ends rather than overflowing the context |
| `command_timeout` | `600` | Seconds per `bash` call |
| `sync_delay_seconds` | `0` | Delay between Airbyte sync triggers (ELT-Bench uses 60 for Databricks) |
| `lora_rank`, `learning_rate`, `kl_penalty_coef`, `max_steps_off_policy` | | Passed through to tinker-cookbook |

## How it fits together

### ELT-Bench inputs

`load_eltbench_tasks(repo, gt_dir, names)` in `task.py` reads one `ELTTask` per benchmark
task from a checkout plus the downloaded ground truth. The two halves of a task never mix:
the agent-visible half is written into the sandbox workspace at the start of an episode, the
grader-only half stays on the host.

| From the benchmark | Read by | Used as |
| --- | --- | --- |
| `elt-bench/<warehouse>/<task>/config.yaml` | `task.py` | Agent-visible. The destination block is stripped on load; `stacks.py` injects the Airbyte credentials and `Destination.agent_config()` writes this rollout's own database back in |
| `elt-bench/<warehouse>/<task>/data_model.yaml` | `task.py` | Agent-visible, the transformation spec |
| `elt-bench/schemas/<task>/*.csv` | `task.py` | Agent-visible, source table schemas |
| `documentation/*.md` | `task.py` | Agent-visible, Airbyte provider documentation |
| `setup/main.tf`, `setup/check_job_status.py` | `task.py` | Agent-visible, copied into the workspace as the benchmark does |
| `evaluation/table.json` | `grading.py` | Grader-only, expected raw-table row counts (stage 1) |
| `evaluation/sql/<task>/*.sql` | `grading.py` | Grader-only, rewritten to this rollout's namespace by `Destination.rewrite_eval_sql()` (stage 2) |
| `evaluation/sort_key.json` | `grading.py` | Grader-only, sort keys used before comparison |
| `ground_truth/gt_<warehouse>/<task>/*.csv` | `grading.py` | Grader-only, the expected data models |

A task defined outside the benchmark uses `load_local_task(dir)`, which expects the same two
halves in a directory layout documented in its docstring. `tests/fixtures/tiny_shop` is an
example.

### tinker-cookbook interfaces

| Cookbook interface | Implemented by | What it does here |
| --- | --- | --- |
| `RLDatasetBuilder` | `ELTDatasetBuilder` (`env.py`) | Builds the train dataset, and an eval dataset when `eval_tasks` is set |
| `RLDataset` | `ELTDataset` | `get_batch(i)` returns `groups_per_batch` group builders, cycling through the tasks |
| `EnvGroupBuilder` | `ELTEnvGroupBuilder` | `make_envs()` provisions `group_size` independent episodes of one task, `cleanup()` tears their resources down |
| `Env` | `build_agent_tool_env(...)` | The multi-turn tool loop. This repo supplies the renderer, the tools, the initial messages, the reward function and the terminal conditions |
| `@tool` / `ToolResult` | `ELTTools` (`tools.py`) | `bash`, `sql`, `submit`. `submit` returns `should_stop=True` |
| reward function | `ELTReward` (`env.py`) | `async (history) -> (reward, metrics)`, called once when the episode ends |
| sandbox interface | `DockerSandbox`, `LocalSandbox` (`sandbox.py`) | `workspace_path`, `run_command`, `read_file`, `write_file`, `kill_background`, `cleanup`, `send_heartbeat` |
| `rl.train.Config` / `main` | `train.py` | The training entry point |
| `do_single_rollout`, `TinkerTokenCompleter` | `rollout.py` | Sampling and grading without an optimizer step |

### The Destination contract

One subclass per warehouse, registered in `destinations/__init__.py`.

| Method | Contract |
| --- | --- |
| `provision(task, rollout_id, from_snapshot)` | Create an empty namespace owned by this rollout, or clone the task's post-EL snapshot |
| `teardown(ns)` | Drop it |
| `agent_config(ns)` | The destination block merged into the agent's `config.yaml` |
| `prompt_notes(ns)` | Warehouse-specific lines appended to the instruction |
| `query(ns, sql, as_agent)` | Run SQL, as the agent's scoped credential or as the grader |
| `table_row_counts(ns)`, `table_columns(ns, table)` | What grading reads |
| `normalize(ident)`, `qualify(ns, table)` | Identifier case folding and fully qualified names |
| `rewrite_eval_sql(ns, sql)` | Provided by the base class, override only for a different SQL dialect |
| `has_snapshot`, `save_snapshot` | Optional, enables `transform_only` |

## Layout

```
src/elt_rl/
  task.py            Task spec. Agent-visible half and grader-only half, kept apart.
  stacks.py          EL stacks: Airbyte (official) and local. Prompts, Airbyte audit API.
  destinations/      Warehouse interface: base.py, duckdb.py, snowflake.py.
  sandbox.py         Per-rollout Docker container (elt-swe image) or local subprocess.
  tools.py           Agent tools: bash, sql, submit.
  grading.py         Two-stage execution grading and the reward function.
  env.py             Episode lifecycle, reward hook, GRPO group builder, RL dataset.
  train.py           Training entry point.
  rollout.py         Run and grade rollouts without training.
scripts/             Local task generator.
tests/               Local integration tests, grading unit tests, parity tests.
```

## Adding a warehouse

Subclass `Destination`: provision an isolated namespace per rollout and tear it down, expose
the connection block the agent sees, run SQL, report row counts and columns, and fold
identifier case. Register it in `destinations/__init__.py`. Tasks, prompts, grading and
training need no changes. `destinations/duckdb.py` is 133 lines and is the smallest example.
